# Testing the Arstro embedded server

Every test names the requirement IDs it proves; results are reported **per requirement**.
Start from `docs/requirements.md` and `docs/traceability.md` (generated by
`python3 scripts/req_coverage.py`, which also lists requirements without any test).

**Which slot?** The server suites talk to the instance picked by `ARSTRO_SLOT` (its control
socket, config, password). Test the slot you just deployed - the idle one,
`ARSTRO_SLOT=$(cd server && python3 -m arstro_remote slots --idle)` - never the one hosting your
own shell (`arstro-remote slots` marks it): the suites restart workers and change passwords. `test_modules.py` needs no installed
slot at all.

## Suites

| Suite | Where | Proves | Command |
|---|---|---|---|
| `server/tests/test_modules.py` | anywhere with python3 (starts its own throwaway instance: slot `t`, temp dirs, free port) | modules on/off, system info, restart, logs, files up/down/edit, IO inventory, UART console over a pty, GPIO (opt-in) | `python3 server/tests/test_modules.py` · `ARSTRO_TEST_GPIO=gpiochip1:30` (a **free** line) adds the GPIO round trip |
| `server/tests/test_daemon.py` | on the board, slot running, desktop on `:0` | protocol, stats, shells, input, Wi-Fi, admin, network profiles (validation only), Bluetooth devices (read only) | `ARSTRO_SLOT=b python3 server/tests/test_daemon.py` |
| `server/tests/test_sync_web.py` | on the board | sync between controllers, web/REST/WS, password (restored), per-port cookie, open mode, CLI local + remote | `ARSTRO_SLOT=b python3 server/tests/test_sync_web.py` |
| `server/tests/test_screen.py` | on the board, desktop on `:0` | remote screen | `ARSTRO_SLOT=b python3 server/tests/test_screen.py` |
| `server/tests/test_recorder.py` | on the board (test pattern, temp storage, restores the source) | preview, recording, settings, conversion, gallery, camera source choice | `ARSTRO_SLOT=b python3 server/tests/test_recorder.py` |
| `server/tests/web/page_smoke.py` | the board (Chromium + X, no Node) | every web page loads without JS errors / overflow; screenshots | `ARSTRO_TOKEN=$(cat ~/.config/arstro-remote-b/web_token) DISPLAY=:0 python3 server/tests/web/page_smoke.py http://127.0.0.1:8081 <dir> [390x844]` |
| `server/tests/web/ui_test.mjs` | a machine with Chrome + Node | the web UI end to end (login, groups, all pages at 4 sizes, preview, record, gallery, shells, touchpad) | `cd server/tests/web && npm install && ARSTRO_URL=http://<board>:8081/ ARSTRO_TOKEN=<password> node ui_test.mjs [--shots DIR] [-k name]` |
| `app/test/*.dart` | a machine with Flutter | codec, terminal dedupe, every screen at 5 sizes | `cd app && flutter analyze && flutter test` |
| `scripts/check_scripts.sh` | anywhere | scripts, and `install.sh` into a throwaway home (slot, port, password, modules, autostart, uninstall) | `scripts/check_scripts.sh` |
| `server/tests/test_repo_policy.py` | anywhere | no environment values / secrets in the repo | `python3 server/tests/test_repo_policy.py` |
| `server/tests/test_agent_policy.py` | anywhere with dbus-python | pairing / authorization policy | `python3 server/tests/test_agent_policy.py` |
| `server/tests/bt_pairing_security_test.sh` | a Linux PC with Bluetooth near the board | pairing window, untrusted devices refused | see the script header |

`-k NAME` runs one test, `--list` shows tests and their requirements. Pass passwords with
`ARSTRO_TOKEN` read at run time from the slot's `web_token`, never write them into files.

## Order for a full check

1. Cheap: `test_repo_policy.py`, `scripts/check_scripts.sh`, `python3 scripts/req_coverage.py --check`,
   `test_modules.py`.
2. Deploy into the idle slot (`arstro.embedded_server.deploy`), then against it:
   `test_daemon.py`, `test_sync_web.py`, `test_screen.py`, `test_recorder.py`, `page_smoke.py`
   (desktop 1280x900 and phone 390x844).
3. Where Node/Chrome exist: `ui_test.mjs`; where Flutter exists: `flutter analyze && flutter test`,
   and the app on a device (pair in the pairing window, or `scripts/dev_tunnel.sh`).
4. Manual items listed in `docs/traceability.md` (Bluetooth pairing, reboot / autostart of both
   slots, real GPIO / I2C / UART hardware on the header).

## Hardware tests (IO Control)

Automated tests never drive pins. By hand, with the user's OK and knowing what is wired:
`arstro-remote-b io header` (states), `io gpio get CHIP LINE` (input, harmless), `io i2c scan BUS`
(probes like i2cdetect), a UART loopback (TX↔RX wire, `io uart open ttySx`), `io pwm set` on a
channel that drives nothing else (on the OPi 5 Plus pwm2/pwm3 are board functions - leave them).
Buses on the header need their overlay enabled (`/boot/orangepiEnv.txt`, reboot - ask first).

## Without the board: local test-pattern server

```bash
SB=<scratch>/sb; mkdir -p $SB/{cfg/arstro-remote-t,state,data,run}; chmod 700 $SB/run
printf '{"web_port": 18088, "bluetooth_enabled": false, "recorder_simulate": "1280x720@30"}\n' > $SB/cfg/arstro-remote-t/config.json
ARSTRO_SLOT=t XDG_CONFIG_HOME=$SB/cfg XDG_STATE_HOME=$SB/state XDG_DATA_HOME=$SB/data XDG_RUNTIME_DIR=$SB/run \
  env -u DISPLAY python3 -m arstro_remote run      # in server/, background; stop it by PID afterwards
```

## Safety rules while testing

- The recorder suites use the test pattern; don't stress the real HDMI input. If a run was
  killed: `arstro-remote-b camera sources` / `rec settings` and restore source and storage.
- Wi-Fi / network tests never disconnect or change a profile (the board may be reachable only
  through it); `wifi_live_reconnect` needs `--wifi-live`.
- Password tests restore the password in `finally`; if a run was killed, check the slot still
  accepts the user's password (copy it back from the other slot's `web_token` with
  `arstro-remote-b web --set-password - < file`, never print it).
- Chromium on the board has no headless mode: `page_smoke.py` places its window off-screen on
  `:0`; it closes it afterwards.

## Reporting

```
Slot B (8081): test_daemon 22/22, test_sync_web 15/15, test_screen 5/5, test_recorder 14/14, page_smoke 18/18 (+ phone width)
Anywhere: test_modules 9/9, check_scripts 26/26, repo policy 2/2, traceability OK
Not run: ui_test.mjs (no Node on the board), flutter (no SDK) - why
```
Never report a suite as passing that did not run; say which ones were skipped and why.
